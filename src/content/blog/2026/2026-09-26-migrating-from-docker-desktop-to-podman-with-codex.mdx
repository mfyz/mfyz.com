I wanted Docker Desktop off my Mac while keeping my usual `docker ps` and `docker compose` workflow. I also wanted everything installed through Homebrew. Pretty straightforward request, until we counted what was already running.

There were 11 running application containers, three stopped ones, and a separate Portainer extension container. MySQL, PostgreSQL, Redis, local websites, a reverse proxy. Across 21 volumes, there was about 23 GB of data to preserve.

Uninstalling the app was going to be the last step.

## Keeping my existing workflow

We installed Podman, the standalone Docker CLI, Compose, Buildx, and credential helpers through Homebrew. Podman runs a Linux VM on macOS; mine ended up with six CPUs and 8 GB of memory. Later in the session, I asked for Podman Desktop too. I still wanted a GUI for looking at containers and logs.

The CLI compatibility comes from pointing Docker at [Podman's Docker-compatible socket](https://podman-desktop.io/docs/migrating-from-docker/using-the-docker_host-environment-variable). Once the Podman machine is running:

```sh
PODMAN_SOCKET=$(podman machine inspect --format '{{.ConnectionInfo.PodmanSocket.Path}}')
docker context create podman --docker "host=unix://${PODMAN_SOCKET}"
docker context use podman
```

The data took more work. We saved the existing images and container filesystem changes, stopped the databases cleanly, and backed up their volumes. Then we restored everything into Podman, preserving ports, mounts, network aliases, and restart policies. Keeping the existing image versions also avoided accidentally turning this into a database upgrade.

The result was the same 11 applications running, with the other three still stopped. Podman Desktop showed the same Compose projects. One detail from testing: our Buildx setup needed `docker build --load` to make built images available locally. Compose builds handled that automatically.

## Having Codex do the migration with me

I gave Codex the outcome I wanted and asked it to check what would be affected. It inspected the machine before changing anything, counted the containers, traced their volumes and Compose files, and recorded the existing web responses.

That inventory was useful immediately. A reverse-proxy route already returned HTTP 502 before we touched anything. Without a baseline, we could easily have mistaken that for a migration problem.

The run had some rough edges. A large MySQL backup stream failed, and the recovery script restarted the original services. Codex changed the backup method to write directly to disk and checked the helper container's exit status before continuing. Homebrew also unexpectedly cleaned up unrelated packages during installation, which Codex then restored. This took retries and actual downtime.

I liked being able to adjust the request while it worked. When I asked for the desktop app, Codex installed it and verified that it could see the existing machine and containers. Privileged cleanup still went through macOS's administrator prompt.

The useful part was how much checking it could carry through: compare PostgreSQL database lists, check the web endpoints again, build and run a Compose smoke test, restart the VM, and confirm that the right containers came back. It also updated my shell helpers and left recovery notes.

I now have Podman Desktop, my familiar Docker commands, and the migrated data. The backups and original Docker VM data are still there. I'll keep those around while I use the new setup for real work.
